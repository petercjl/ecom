# 独立店铺管理页验收（2026-11-02）

## 验证范围

macOS arm64 Component Dev，源码版本 `592728afc1a7622518ea3d2f5ff383f3166aef06`。通过统一入口 `node ecom/build-dev.mjs` 构建并正常重启，复用原有 Dev 数据目录。最终构建为 3 个步骤、1 分 37.58 秒，包含构建图检查、资源生成、原生编译与链接；该耗时不是单一 C++ 文件的编译耗时。

## 已通过

- 原生内置页 `ecom://shops/` 正常加载本地静态资源，通过受信任 WebUI 消息调用与 CLI 相同的店铺能力。桌面工具栏提供网格按钮；重复点击复用已有管理标签页。
- 真实界面显示原有三个容器：两个淘宝店铺及一个普通容器。两次构建重启后 ID、名称、平台配置及待验证状态保持一致。
- 界面搜索将列表过滤为一个目标店铺；平台分类显示两个淘宝店铺；已核验筛选显示空列表，符合实际状态。
- 添加弹窗显示平台、店铺名及创建／登录／核验步骤。提交已有店铺名称返回 `CONTAINER_NAME_EXISTS`，原有记录未被覆盖，未产生新容器。
- 内容设置页保留容器启用、外观和排序功能，以及独立管理页链接；完整店铺列表已移至独立页面。
- 真实 CLI 的 `shops manage`、`shops list` 和指定既有容器的 `shops open --service sycm` 成功。原生打开操作核对了实际 WebContents 容器 ID；新增服务标签与原有标签位于同一 Ecom 窗口。该项验证入口及容器归属，不表示完成该服务的登录或身份核验。
- 18 项 Node 测试通过；资源名调整后重新运行 3 项管理模型测试通过。测试覆盖分类／状态／身份搜索、所有服务入口保持目标 containerId，以及确认命令必须使用本次候选身份。原生 C++、设置页 TypeScript 与样式检查通过实际构建验证。
- 重启脚本检查普通有界面模式、主进程无 TCP 监听及无远程调试／无头／自动化启动参数。

千牛与万相台的真实登录／权限、Windows 原生页面与通信，以及多店完整身份验收尚未完成。管理页的入口与界面验收不替代这些测试。
