# P2：按需恢复与恢复并发验收

2026-11-06，macOS arm64 Ecom Dev。P2 已编译、正常重启并通过原有标签验收。最终配置为按需启动开启、后台恢复并发 2、自动闲置休眠开启且阈值 20 分钟。

## 内存结果

保留原有两个窗口、7 个标签：每窗口各 1 个选中内置页，其余为商家中心、生意参谋和 3 个小红书页。6 个已保存账号容器的 ID、名称和标签归属保持一致。启动采样期间不切换标签、不取数、不清理缓存或网站存储。

| 指标 | P2 前 | P2 首轮 | P2 最终复测 |
| --- | ---: | ---: | ---: |
| 启动 120 秒采样峰值 | 2177.48 MiB | 599.84 MiB | 649.68 MiB |
| 峰值降幅 | — | 72.45% | 70.16% |
| 约 120 秒末端 | 1869.57 MiB | 326.07 MiB | 338.07 MiB |
| 末端降幅 | — | 82.56% | 81.92% |
| 末端进程数 | 15 | 7 | 7 |
| 待恢复后台页 | 0 | 5 | 5 |

收益来自后台页延后加载。访问或显式恢复页面后，其运行内存会增加。另一次关闭按需模式、并发 2 的启动验证中，5 个后台页全部通过队列加载完成，采样峰值 2203.53 MiB；并发控制限制加载重叠，不能消除全部加载完成后的常驻开销。

采样使用 libproc `proc_pid_rusage` physical footprint，将 Dev 主进程及子进程按 PID 去重汇总，每约 0.5 秒采一次；三组主对照各采满约 120 秒，所有 OS 采样完整。末端进程数包括进程树中的辅助进程，不包含脱离该树的 crashpad。属于离散采样峰值，短于间隔的尖峰可能遗漏。原生 GUI／CLI 快照另按约 5 秒采集。首轮对照关闭自动休眠以隔离启动策略；最终复测启用 20 分钟自动休眠，120 秒窗口内未触发卸载。

这是相同保存标签集合与选中状态的本机重启观测；动态站点、缓存、网络及系统压缩状态会变化。没有将不同工作负载下 Chrome／Brave 的历史数值用作本轮同条件比较，也不据此推断网页加载后的引擎内存效率。

## 行为与会话验收

1. **按需启动与切换**：重启后 5 个后台网页保持 deferred/unloaded，未创建其网页渲染进程。点击原有“小红书收纳”标签后在原容器加载，另外 4 个保持待恢复；页面显示搜索内容、已有账户入口和通知。
2. **后台排队与前台优先**：并发设为 1，4 个原有后台标签同时请求恢复，1 个开始、3 个排队；观察峰值始终为 1，最终全部 ready。切换其中一个排队的小红书页时，其 startedAt 早于当时后台页 finishedAt，证明用户切换不等待后台槽。记录查询与 GUI 共用原生请求 ID。
3. **启动模式与持久化**：GUI 关闭按需启动、设并发 2，CLI 回读一致；再次通过统一脚本重启，5 个后台页全部入队并完成，记录峰值为 2。恢复按需启动与自动休眠默认设置后再次重启，5 个后台页继续保持待恢复。
4. **GUI／CLI 一致性**：GUI 保存并发 1，CLI 回读为 1；CLI 休眠原有抱枕标签，GUI 后台恢复成功，CLI `memory operation` 回读其 currentRestore.phase=ready。最终 GUI 显示按需恢复、并发 2 和待恢复数量。
5. **原生后台取数**：首轮和最终重启均在原有网页待恢复时，对同一已绑定淘宝容器执行 `shop.trade-summary`，参数固定为 dateRange=2026-10-29|2026-11-04、dateType=recent7、device=0。均 HTTP 200、businessStatus=success，服务认证及绑定身份核验通过；取数后原有标签及选择保持不变。该验证证明请求和身份通路正常，不对返回经营指标或日期完整性作额外业务判断。
6. **页面辅助取数**：同一小红书容器后台搜索“收纳”，首轮返回 18 条、最终返回 18 条，临时页均关闭，原有 5 个后台页仍待恢复，当前选择未改变。小红书的可用搜索与登录界面证据单独记录，未接入独立的平台账号身份核验器。

## 实现与契约

原生 session restore 保留导航条目与容器 SiteInstance／StoragePartition，通过包装原有恢复入口只将每窗口选中页交给启动加载器。Profile 级恢复服务管理后台队列；入队和开始前核对标签、容器、页面版本及 URL，关闭或目标变化清理旧请求，失败状态可读。显式排队容量 32，完成历史有界；自动恢复队列按实际恢复标签数建立。最终实例的真实错误目标测试分别返回 PAGE_CHANGED 和 TARGET_MISMATCH，均 executed=false。

GUI 新增“重启与按需恢复”。CLI 增加 `memory restore status` 和 `memory restore set --lazy-startup on|off --max-background 1..4`；`tabs wake` 支持待恢复及已卸载页，并返回 navigation-started／navigation-queued 与 requestId。`memory operation` 返回 currentRestore，快照包含 restoration 和逐页 restore。匹配的服务页复用也走同一恢复队列，CLI 保留其恢复状态。能力清单、参数、README 和 canonical Skill 同步维护。

默认后台并发 2，降低限制不终止正在加载的网页；槽位保持到停止加载或关闭。用户选中页直接加载。纯原生网络取数不依赖网页常驻；新建页面取数沿用原有任务并发与保护，普通用户导航及网站子请求不受本恢复队列统一限流。Web 平台持久会话由原容器托管，网页运行态、登录有效期及 SessionStorage 的恢复仍遵循原生语义。
