## 内存实测结论

同一运行实例、2 个窗口、原有 7 个标签，自动卸载 1 个合格后台页后，总 physical footprint 中位数从 **1917.84 MiB 降至 1580.29 MiB，减少 337.55 MiB（17.60%）**；唯一进程数从 15 降到 14。

| 阶段（北京时间） | 采样数 | 总内存中位数 | 采样范围 | 进程数／标签数 |
| --- | ---: | ---: | ---: | ---: |
| 自动休眠前 14:01:45–14:02:45 | 5 | 1917.84 MiB | 1865.09–1921.82 MiB | 15／7 |
| 自动休眠后 14:05:49–14:06:50 | 5 | 1580.29 MiB | 1579.93–1581.70 MiB | 14／7 |

各阶段间隔约 15 秒采样，均为完整指标；两阶段之间没有重启。指标为 macOS physical footprint（1024² 字节／MiB），包含压缩内存记账，不等于 RSS 或 JS 堆。每个唯一进程只计一次，不用标签均分估算计算收益。

本次用 60 秒闲置阈值缩短验收时间。标签句柄 6 由调度器自动卸载；另一个候选页 7 存在可显示的离开确认，因此保持运行。三个其他业务页在本次对照中临时设置保持运行，避免扩大实验范围。7 个标签的标题、origin、容器归属及两窗口选中标签保持一致，选中句柄始终为 2、1。测试结束移除全部临时保持运行设置，并恢复 1200 秒阈值。

这是当前动态网页、顺序采样下的实测结果；缓存、GC 和其他页面活动可能共同影响总量，不能把全部差值解释成单页独占内存，也不能承诺固定节省比例。上次手动 MVP 卸载了两页，本次实际自动卸载一页，二者不能按百分比直接比较调度优劣。脱敏原值见 [自动休眠对照 JSON](memory-auto-comparison-2026-11-06.json)。

内核可识别的表单／编辑、上传、锁、WebRTC、设备、固定标签、通知、策略例外及关联页保护继续生效。本轮没有覆盖所有网站自定义编辑模型、全部上传／设备组合或任意外部 Agent 工作流；无法从原生状态识别的业务任务／客服，应先显式保持运行，完成后释放。

## GUI 与 CLI 的共同契约

GUI 入口为「账号管理 → 内存与标签页」，提供自动休眠开关、闲置分钟数、检查与卸载计数、逐页等待／保护原因，以及“保持运行”和手动休眠／恢复。按需刷新资源快照；调度不做常驻内存采样。内核自带 Memory Saver 状态与 Ecom 自动休眠单独展示。

```sh
ecom-cli memory auto status --instance INSTANCE --json
ecom-cli memory auto set --enabled on --idle-seconds 1200 --instance INSTANCE --json
ecom-cli tabs protect --tab ID --container ID --expected-page-version VERSION --keep-awake on --instance INSTANCE --json
```

自动设置作用于选定普通 Profile，持久保存；支持 60–86400 秒。关闭停止新的扫描，不主动加载已休眠页。启停／修改阈值、导航／恢复及集成页面任务结束后重新计时；启动后先经过完整闲置期，避免集中卸载恢复会话。保护条件及目标在同一 UI 执行任务中重检，无 force 入口。

单页保持运行按稳定标签句柄绑定，跨该标签导航保留，持续到明确释放、关闭标签或浏览器重启；它不会唤醒已卸载页。外部页面任务先开启保护，完成或取消时读取新页面版本并以 `--keep-awake off` 释放；未知结果读取快照核实。纯原生网络请求复用容器存储，不依赖网页常驻。

自动状态公开最近 32 条动作引用，动作详情复用最近 128 项操作记录。执行后身份或卸载状态不明确会暂停新自动卸载；检查后关闭再开启恢复。持久 Cookie、LocalStorage 等由原容器托管，休眠不清理会话存储；网站登录与自定义运行态的恢复仍由平台规则决定。
