# P1 手动休眠 MVP 验收（2026-11-06）

P1 已在 macOS arm64 Ecom Dev 完成 GUI／CLI 手动休眠与后台恢复。同一运行实例、相同 7 个标签，休眠两个闲置小红书搜索标签后，总 physical footprint 中位数从 **1884.04 MiB 降至 1405.33 MiB，减少 478.71 MiB（25.41%）**。本轮交付显式单标签操作；自动 Memory Saver 设置保持关闭。

## 实测对照

原生源码：`19f0d5ff361cb8b29b8e679e855b0648dfd66e97`。使用统一 `node ecom/build-dev.mjs` 增量编译、正常退出并重启 Dev；以下三阶段之间没有重启。固定 Dev Profile、2 个窗口、7 个标签和 6 个保存账号；只有两个闲置标签（句柄 6、7）的卸载／加载状态发生预期变化。两窗口的选中标签始终为句柄 2、1。浏览器保持普通有界面模式，无调试端口或调试管道。

每阶段采样 5 次、间隔约 15 秒，总量只累计唯一进程一次，所有采样完整。单位 MiB（1024² 字节），口径为 macOS physical footprint，包含压缩内存记账，并非 RSS 或 JS 堆。

休眠阶段首次采样仍为 1642.51 MiB，后续资源释放后约 1405 MiB。恢复阶段有页面重新加载、GC、缓存及其他动态页面波动，内存不会必然回到原基线；恢复后较低的总量不能全部归因于休眠策略。该实验直接证明本次两个闲置页卸载有实际收益，不构成所有站点或十店铺场景的固定节省比例。标签／容器均分估算不用于计算本次收益。

恢复通过标题、origin、稳定标签句柄、原容器归属、页面版本及加载完成状态核对。第二个 CLI 恢复请求发出后约 7.26 秒观测到两页均已加载就绪；这包含真实联网耗时，不是独立页面延迟基准。验收结束再次将这两个标签休眠，保留全部标签和前台状态。

原始数据的脱敏汇总见 [比较数据 JSON](memory-p1-comparison-2026-11-06.json)。完整私有采样、操作记录和构建日志位于本机忽略提交目录 `.brave-build/memory-p1-evidence-x1k8mhhm/`。

## 已交付行为

- GUI「账号管理 → 内存与标签页」分别展示自动资格、手动休眠条件与保护原因；符合条件的标签可休眠，已卸载标签可恢复。GUI 休眠前确认目标及重新加载影响，取消保持原状态。
- CLI 提供 `tabs discard`、`tabs wake` 与 `memory operation`，要求明确实例、标签、容器和页面版本。GUI／CLI 调用相同原生能力与校验，后台恢复保持用户活动窗口及标签。
- 使用原生 PROACTIVE 卸载校验，并为手动操作保留 30 秒最近使用保护，以及活动／可见、编辑表单、媒体、固定标签、通知、策略例外等限制；增加加载、上传、WebRTC、锁和已接入原生页面任务保护。自动调度策略保持原有设置。
- `tabIdKind=native-tab-handle`：标签 ID 使用 TabInterface 句柄，在卸载替换 WebContents 时保持不变，只在当前实例内使用。页面版本用于检测导航变化，窗口 ID 单独标识窗口。
- 动作结果保留最近 128 个，超时或连接未知先查询。恢复结果 `navigation-started` 仅代表开始导航；网站加载和登录需另行检查。

持久 Cookie、LocalStorage 等由原容器继续托管，休眠不清理存储。未保存的页面内存态和平台会话行为遵循网页及原生保护机制；本轮核对容器与页面恢复，没有另行核验所有平台登录身份。
