# 双容器后台取数测试（2026-11-02）

## 结论与范围

macOS arm64 的同一个 Ecom Dev 实例中，两个用户已登录的持久容器均可通过 sycmcli 原生会话入口读取生意参谋交易概况。三轮六笔请求全部返回业务码 0；每个容器的完整业务数据指纹在三轮保持一致，两容器指纹始终不同。本轮未发现容器响应混用。用户确认后台取数期间使用正常，未感知窗口闪动、标签切换、输入焦点被抢或明显卡顿。

此结论覆盖同一接口、同一天数据、两个容器的交替与同时取数。当前结果仍为 `identityVerification: container-selection-only`；它证明两条容器会话返回独立、稳定的数据，不能替代平台 shopId 与容器绑定验证，也不能据此承诺所有账号状态、接口和并发规模均无串用。

## 方法

使用项目脚本 `ecom/experiments/native-multicontainer-probe.mjs`，通过实际 sycmcli 入口调用 `ecom run shop.trade-summary`。先解析两个唯一现有容器，固定 ID 与浏览器实例；参数固定为 `dateType=recent1`、`dateRange=2026-11-01|2026-11-01`、`device=0`。不操作可见页面、不改店铺账号、不复制 Cookie。网站会话由 Ecom 存储分区网络服务使用。

| 轮次 | 顺序 | 成功请求 | 单命令耗时 |
| --- | --- | --- | --- |
| 1 | A → B | 2/2 | 2.309 秒、3.355 秒 |
| 2 | A、B 同时 | 2/2 | 1.989 秒、1.987 秒 |
| 3 | B → A | 2/2 | 2.381 秒、2.174 秒 |

A、B 代表用户指定的两个店铺容器。耗时包括 Node/CLI 启动、本地进程与容器检查、HTTP 请求及结果读取，不能视为纯网络延迟或持续性能基准。三轮运行于北京时间 09:23:47–09:24:17，包含两次 8 秒间隔。日志记录独立操作 ID、单一实例、容器 ID 和响应指纹；真实店铺名称、ID 与经营数据仅保存在忽略提交的私有证据中（目录 0700、文件 0600）。

脚本接受显式 sycmcli 模块、两个容器与日期，仅发起六笔注册 GET；遇到失败即结束当前测试，不自动重试。各次运行创建独立证据文件，不覆盖已有结果。

## 对正常浏览的观察

通过原生辅助功能只读观察 Ecom，未使用 CDP、调试端口、调试管道或无头浏览器。09:23:22（请求前）、09:24:04（同时取数中）、09:24:38（完成后）三次采样结果一致：

- 选中的页面为用户原先的万相台首页，地址栏保持原 URL。
- 当前容器保持 B，标签数保持 5，焦点元素仍为同一网页 HTML 内容。
- 没有发出点击、导航、切换标签或激活窗口动作。
- Dev 主进程保持原 PID，监听检查未发现 TCP 端口。

这些采样没有发现页面或焦点被取数操作改变，但不构成连续录屏，也不能排除采样间极短的闪动。用户随后对这轮实际使用体验反馈“没有，使用正常”，与三次采样结果一致。本轮实际使用体验验证通过；该测试不测量整机 CPU/内存增量或输入延迟。

## 关闭业务页面后的复测

用户关闭业务页面后，通过原生辅助功能确认 Ecom 界面仅保留一个 `chrome://newtab/` 新标签页；原 Dev 主进程与实例 ID 保持运行。随后同时对 A、B 各执行一次同参数 `shop.trade-summary`：两笔均返回业务码 0，各自完整业务数据与此前对应容器的结果一致。单命令耗时分别为 A 0.758 秒、B 0.713 秒。

取数后界面仍只有原新标签页，没有打开业务页面。本次通过实际 CLI 复测确认：此接口依赖运行中的 Ecom 容器会话，不依赖保持商家网页打开。本次没有测试完全退出 Ecom、零标签零窗口、浏览器重启或长期后台存活；不能将结论扩大到这些条件。

原始响应保存在本地私有证据中，未写入仓库。浏览器及店铺会话未被重启、复制或切换，未启用 CDP。
