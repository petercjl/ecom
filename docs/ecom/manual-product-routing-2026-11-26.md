# 商品页手动规则跳转

## 行为与责任

淘宝商家容器中的商品链接匹配已启用的买家跳转规则时，先在原容器打开。平台明确拒绝商家查看他店商品时继续使用自动跳转。已出现图库、主图去重后为 1–3 张的页面显示原生提示条“商品详情可能不完整”，按钮为“按照规则跳转”。此提示只提供用户选择，不将图片数量视为访问受限的证据。

图库取一次加载完成后的样本；若页面持续加载，最多等待五秒后使用已有图库。图片数量读取复用页面 DOM，不请求额外图片，不对商品进行补充搜索或详情完整性探测。展示提示条后停止页面观察。用户可关闭提示条并继续浏览。

原生提示条负责展示和用户操作；既有原生路由能力负责重新检查规则、目标账号与跳转执行；买家商品流程负责取得有效链接。网页不能调用提示条的原生回调。点击动作绑定当前文档、商品 URL 和容器，文档或容器变化后失效。规则配置变化会移除已有提示条；规则关闭、没有匹配规则或已在目标容器时不会创建此提示条。重复点击仅执行一次。

## CLI 契约审查

现有 CLI `routing list/test/enable/disable` 与提示条复用原生配置和规则校验。配置变化通过原生偏好订阅立即撤销提示条。URL 预览仍表示规则匹配，不表示已观测到页面不完整。

当前新增按钮是原生 UI 操作；CLI 尚无针对具体标签的手动规则跳转命令，此项明确保留为能力缺口。没有扩展网页脚本权限或把 CDP 作为正式版功能实现。

## 验收边界

macOS Dev 验收包含受控三图页面、原生按钮操作、规则关闭撤销、完整图库及真实买家跳转。受控页面仅验证交互与分支，不能代替淘宝真实受限响应的证据。Windows 和正式发布包另行验证。本轮不发布 npm。
