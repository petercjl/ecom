# 网址打开规则：URL → 指定容器

状态：用户已确认的产品需求。日期：2026-11-20。GUI、原生规则与 CLI 的实现及平台验收单独记录。

## 目标与示例

用户将一批网址或网址匹配条件绑定到一个既有容器。普通浏览命中规则时，Ecom 使用目标容器的原生会话打开页面。规则面向任意网站，淘宝／天猫详情页是首个配置示例。

用户反馈的场景：店铺账号访问其他商品详情受限，因此店铺后台继续使用各自的店铺容器，商品详情统一使用用户选择的买家容器。平台限制作为需求背景；本设计不将规则名称、容器名称或 Cookie 存在等同于真实登录和访问权限证据。

预置规则“淘宝／天猫商品详情”仅适用于商家容器中的导航；目标“淘宝买家”；多条匹配条件为“或”关系。软件内置并预填该示例，目标容器留空，规则默认关闭。用户自行选择容器并保存后，仍需手动开启才生效；示例与自建规则共用编辑和测试能力。

| 协议 | 精确域名 | 路径 | 查询参数条件 |
| --- | --- | --- | --- |
| HTTP 或 HTTPS | item.taobao.com | /item.htm | id 存在且为非空值 |
| HTTP 或 HTTPS | detail.tmall.com | /item.htm | id 存在且为非空值 |

这些是可编辑示例，并非完整淘宝链接目录。手机详情页、新域名和短链按用户需要新增；平台页面结构变化通过编辑规则适配。

## 设置入口与交互

账号管理页 `ecom://shops/` 增加“网址打开规则”入口，设置中的容器管理链接可到达同一页面。

规则列表显示：启用状态、名称、匹配条件数量、目标容器名称／颜色、优先顺序，以及编辑、复制、删除操作。列表上方提供全局启用开关和“添加规则”。无配置时保持当前浏览方式。

添加／编辑规则包含：

1. **规则名称**：便于识别用途，例如“淘宝商品详情”。
2. **匹配网址**：一条规则可以添加多条条件；支持粘贴完整 URL 列表、精确网址，以及域名／路径匹配条件。
3. **使用容器**：从既有持久容器中选择，显示名称、平台及颜色，内部保存稳定 containerId。提供管理容器入口。
4. **测试网址**：粘贴一个 URL，显示命中条件、最终生效规则和目标容器；仅做本地匹配，不访问网站。
5. **启用与保存**：原生校验通过后一次保存；输入错误就地标明，保留未保存内容。

粘贴实际商品链接时，默认按精确网址加入；界面另提供“匹配同类网址”，让用户确认域名、路径和参数条件。示例中的商品 id 只用于识别页面类型，不默认固定为某个商品值。

## 匹配合同

首版提供两类条件：

- **精确网址**：匹配规范化后的完整 HTTP(S) URL，忽略片段（# 后内容）；保留路径及查询参数的区分。适合指定一批具体链接。
- **域名和路径**：协议选择 HTTP、HTTPS 或两者；域名默认为精确匹配，可显式选择包含子域；路径支持精确值及星号通配。查询参数可选“存在”“等于指定值”。适合同一类详情页。

同一行的域名、路径和参数为“且”关系；同一规则的多行为“或”关系。参数条件按解析后的键值匹配，不受参数顺序影响；重复同名参数默认任一值满足即命中。全局规则按列表从上到下查找，第一条启用且命中的规则生效，测试区明确显示冲突及最终结果。

匹配使用 URL 解析结果，域名大小写归一化并校验标签边界，路径保留大小写和编码语义；不能靠“包含 taobao.com”等任意文本判断域名。`item.taobao.com.example.org` 和其他网站查询字符串中的淘宝链接均不命中精确淘宝域名条件。输入含用户名／密码、非 HTTP(S) 协议或无效模式时拒绝保存。

规则保存在浏览器当前普通 Profile 下，跨该 Profile 的窗口生效；正式版与 Dev 配置独立。目标按稳定容器 ID 绑定，重命名和改色后继续有效。目标限于持久容器，避免临时容器生命周期导致归属不稳定。

## 打开行为

- 地址栏输入、粘贴、普通链接点击、新标签打开、弹窗及可识别的顶层跳转，统一进入原生路由判断。匹配在该目标 URL 的请求发送前完成。
- 目标容器与当前容器相同时，沿用原有导航及前后台行为。
- 目标容器不同时，在同一 Ecom 的新标签里使用目标容器打开；保留来源标签的页面、输入内容和店铺登录态。当前标签直接导航默认切到新目标标签；明确的后台打开继续保持后台。
- 预置商品规则根据当前容器的账号类型判断来源。买家和默认容器跳过这条预置规则，自建规则继续按列表顺序匹配。仅输入网址的测试按商家来源预览这条预置规则。
- 用原始网址匹配规则。命中内置淘宝／天猫商品详情示例时，跨容器准备链接只保留一个数字商品 `id`，并使用原商品域名的 HTTPS 详情页。已配置的示例继承此行为，容器和开关沿用原配置。其他规则可选择同一处理方式或保留原网址。
- 重复、缺失或非法的商品 ID 会阻止整理后的跨容器导航。整理后的地址若命中另一个容器，停止打开并提示检查规则顺序。网址测试显示将打开的跨容器地址或阻止原因。

- 为本次打开新建的初始空白标签，在目标容器标签成功创建后自动关闭。以 Chromium 的初始空白导航状态识别，并在关闭前再次检查；已有页面、恢复标签和克隆标签保留。
- 规则只决定本次页面的容器，不把来源标签、整个店铺或整个域名永久改绑。买家容器中需要登录时，在该买家容器手动完成。
- 跨容器创建新的浏览上下文，不复制 Cookie、LocalStorage 或店铺页面状态；不复用来源窗口的 opener 脚本关系，也不向目标透传来源页面的认证头和敏感来源信息。
- 开启或编辑规则时，已打开页面保持原样；后续打开和跨文档导航应用当前规则。恢复已保存会话的标签保留其原容器，后续导航再按规则判断。

后台图片、脚本、接口请求、iframe 以及页面内片段跳转保持原容器。POST／表单提交若命中其他容器，阻止跨容器自动重放，提示使用目标容器打开页面后重新操作。登录和验证码仍由用户完成。

短链在展开前无法仅凭 URL 确定最终目标。每次顶层重定向在请求下一跳之前重新判断；最初未命中的短链请求可能已在来源容器发生，不能宣称短链从第一跳起完全使用目标容器。用户可另外配置短链入口规则。登录跳转和多条规则组合须有环路检测，避免反复跨容器打开。

## 异常与恢复

- **规则目标已不存在**：保留规则并显示失效；命中的页面停止自动打开，提示重新选择容器，避免静默回到店铺会话。
- **删除被规则引用的容器**：删除预览列出引用规则，要求先停用或改绑后再按既有容器删除流程处理。
- **未登录或平台拒绝访问**：在目标容器中提示平台实际状态；路由成功与页面业务成功分别报告。
- **多条规则重叠**：按顺序取首条，测试区显示被遮蔽规则；允许用户调整顺序。
- **循环路由**：停止本次路由链并提示规则冲突，保留已有页面和会话。
- **关闭全局开关**：保存规则内容，后续导航恢复普通容器继承行为。

## GUI、CLI 与实现责任

共享原生能力层负责规则持久化、URL 规范化与匹配、稳定容器查找、冲突处理和导航拦截。GUI 与 CLI 都调用该层；网页和业务 Skill 不能自行改写浏览器 Profile 文件。业务 Skill 决定何时需要买家浏览，浏览器规则不推断用户的商品研究策略。

CLI 使用独立的 `routing` 命令组，实际参数见能力清单。

| 拟议能力 | 输入／输出重点 |
| --- | --- |
| list / inspect | 规则 ID、顺序、条件、开关、目标容器 ID 及有效性 |
| save / set-container / enable / disable | 与 GUI 相同的校验、持久化和配置修订号 |
| set-transform | 修改单条规则的网址处理方式，保留目标、匹配条件和开关 |
| delete / reorder / set-enabled | 精确规则 ID，校验完整顺序及配置冲突 |
| test | URL、可选来源容器；返回是否命中、命中条件、规则 ID、目标容器及计划行为，零网络请求 |

普通 GUI 浏览遵循规则。Agent 已明确指定容器的后台请求、页面任务及取数保持固定任务身份；若规则与显式目标冲突，返回可审查的 `URL_CONTAINER_CONFLICT` 和建议目标，而非静默切账号。原生网络 session request 不执行导航重路由；应用 Skill 根据错误或测试结果明确选择正确容器。通用导航 CLI 如需跟随规则，须显式选择并回报实际目标容器。

CLI 功能开发需要同步能力清单、schema、结构化错误、测试及 npm 包的 canonical Skill，并按项目的能力包与 portable Skill 流程实施。已实现的命令和浏览器版本通过能力清单及本机实例查询。

现有源码可复用的接入点：

- `browser/ecom/shop_manager_ui.cc`：账号管理页及可信 WebUI 消息入口。
- `browser/ecom/shop_container_service.*`：GUI 与 CLI 共享原生容器操作的既有模式。
- `chromium_src/chrome/browser/ui/navigator/browser_navigator.cc`：导航参数及原生容器继承。
- `browser/brave_content_browser_client.cc` 的导航节流器注册：顶层请求及重定向阶段的统一拦截候选。
- `components/containers/content/browser/storage_partition_utils.*`：容器与存储分区映射。

接入前须验证各导航来源实际覆盖；单改界面打开按钮或等待页面加载完成再移动标签，不满足请求前路由要求。

## 验收顺序

1. 匹配单测：精确 URL、路径通配、参数顺序／缺失／重复、域名边界、片段、优先级、失效容器和环路。
2. 原生本地双容器站点：记录网络请求携带的会话标识，验证匹配详情页没有先用来源容器请求；覆盖地址栏、普通点击、后台标签、弹窗及重定向。
3. 确认 POST 不被重放，后台请求／子资源归属不变；来源编辑内容、选中标签、前后台打开意图及 opener 隔离符合合同。
4. GUI 和 CLI 对同一规则取得相同测试结果；配置重启保留、容器改名保留绑定、删除引用有明确处理。
5. 在用户实际店铺容器与买家容器中分别人工登录，实测淘宝／天猫详情跳转、登录跳转、未登录和失效状态；macOS 与 Windows 分别记录结果。

首版交付重点是规则配置、真实请求前路由和可验证的容器归属。性能与网站兼容性以实际测量为准。
