# 商家商品归属与条件跳转

## 行为

已启用的淘宝／天猫商品规则指向淘宝买家容器时，淘宝商家容器先按原始链接正常导航。平台允许打开的本店商品保留在当前容器，直接显示详情；仅平台明确返回“商家账号不支持访问其他店铺商品详情”时，才进入既有买家商品短链接／标题搜索流程。替换此次被拒绝的商品标签，保留商家来源页。

判定来自本次实际商家导航的页面，不按容器名称、商品标题或链接来源猜测归属。不添加商品点击缓存，不额外拉取本店商品详情或枚举店铺商品库。平台未给出明确他店判定时保留原页面；登录、验证码、网络错误、下架及普通访问异常不能视作他店证据。

## 原生实现与边界

- 原生导航规则仍统一处理开关、来源容器、目标容器、POST、循环及明确绑定账号的任务。仅符合既有买家商品规则且来源为淘宝商家时启用页面观察。
- 观察范围为原商品 ID 对应的淘宝／天猫详情页，或同一导航链中的 HTTPS `bixi.alicdn.com/punish/punish:resource:template:CDCBusinessDataSecuritySpace:` 平台判定页。真实平台他店商品已观测到此重定向。
- 隔离世界仅读取页面可见内容：必须同时有拒绝页面标题、店铺数据安全提示和他店商品拒绝文字，且无商品图库或验证提示。通用登录页不触发买家跳转。
- 观察随用户导航、无关跳转、文档替换、容器改变或关闭失效。最多观察 15 秒，不阻塞正常加载；成功显示图库后停止。触发前重查规则及目标，规则变化后保留当前页面。
- 买家导航使用原有容器隔离与凭证边界，不携带商家请求头、表单或来源参数；原始商家导航保留原链接。

## CLI 共同契约

现有 `routing list/test` 仍通过同一原生规则服务执行。CLI 本地测试不访问网站，也不宣称已经知道商品属于谁。适用规则的 resolution 增加 `ownershipCheck: merchant-page-verdict` 与 `onUnknownOwnership: stay-in-source`；`openMode: buyer-product-search` 表示确认他店后的买家处理方式。界面预览同步显示条件目标，规则的匹配条件和开关命令保持兼容。

本次修改原生浏览器与其 WebUI，既有 CLI 透传原生结果，无 npm 包发布。显式指定容器的 Agent 页面任务继续遵循现有固定账号契约；本次不开放自动改换 Agent 任务账号。
