# 小红书普通图文笔记 CLI

应用层决定标题、正文、话题和图片顺序。Ecom 接收明确的清单，在指定原生容器中核验创作账号、上传并回读表单、执行单次提交及查询结果。运行入口为 macOS Ecom 的 `xhsNoteProtocol: 1`，配合本仓库 `packages/ecom-cli`。CLI 默认连接正式版，开发时用 `--profile` 或 `--instance` 指定 Dev。正式验收应显式指定正式候选的数据目录或实例，回环测试入口限 Dev 使用。浏览器使用普通桌面模式和认证的私有本地信箱，网站凭据由对应容器保管。

输入是 UTF-8 JSON 对象：`title`、`body`、可选的 `topics`（不带井号的名称）和按发布顺序排列的 `images`（绝对路径或相对清单的路径）。本地限制为单行标题 20 个 UTF-16 单元、正文含话题 1000 个 UTF-16 单元、1 至 18 张 PNG/JPEG、单张 10 MiB、合计 24 MiB。话题作为普通井号文本附在正文末尾。平台话题选择器、商品挂载和视频有各自的操作契约，本能力未覆盖。

| 命令 | 行为和完成依据 |
| --- | --- |
| `xhs note preflight` | 仅检查本地清单及图片。返回可核对的内容、顺序、图片 SHA-256 及整体摘要。 |
| `xhs note open` | 在选定小红书容器中后台打开[创作页](https://creator.xiaohongshu.com/publish/publish)，返回准备 ID。账号身份来自真实创作服务响应；容器名称仅供定位。 |
| `xhs note upload` | 绑定实例、容器、账号和素材摘要，按序上传图片。`images-ready` 表示预览已齐。 |
| `xhs note fill` | 使用同一准备 ID 和素材摘要，分别填写标题和正文。已匹配的字段跳过，发现不同的现有内容则保留并报告。 |
| `xhs note verify` | 只读核对有序预览、标题及正文。`content-verified` 表示内容匹配，发布按钮状态单独报告。用户在原标签检查后点击发布。 |
| `xhs note prepare`（兼容入口） | 绑定实例、容器、准备 ID、已确认的创作账号 ID 与已审核的素材摘要。上传图片并填写空白表单；平台可能保存草稿。只有读回标题、正文、预览数量及可用发布按钮后才返回 `form-ready` 和确认串。 |
| `xhs note submit` | 调用方必须明确授权发布，并传入本次确认串。先持久记录尝试，再实时复核创作账号、表单内容和有序预览，满足条件才点击一次发布。 |
| `xhs note status` | 查询原准备 ID 的表单或提交结果。浏览器重启后，表单需重新准备，已记录的提交尝试仍可从原数据目录查询。 |

`not-submitted` 表示点击前已拒绝；`submitted` 表示创作页明确确认接收；`published` 要求可核对的创作成功证据及笔记 ID。只观测到点击、导航中断或无法核实平台反馈时，按 `submission-unknown` 处理，并保留准备 ID。在原容器的创作平台笔记管理中核对结果。同一容器及创作账号下，未确认的尝试会拦截同一内容摘要的新准备和提交。

登录或风控验证在原容器刚打开的创作标签中人工完成；完成后用同一准备 ID 查询。若用户离开原文档，准备失效。CLI 的 `help --json` / `schema --json` 提供参数、状态及错误；配套 Skill 提供 Agent 的执行说明。
